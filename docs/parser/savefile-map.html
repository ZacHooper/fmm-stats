Every region

Each row names the region, says what it holds, and tags how the parser finds where it starts and proves where it ends. The second tag is the name of the parser code that reads it. Named regions link to their table doc; an unread region links to a page of what is known about it so far (all unread regions).

count in front
A number sits just before the first record and says how many follow. Read that many and check you land on the next table.
fixed grid
Equal-sized slots reserved up front, many still empty. Found by the record's own pattern; the slot count is room, not a headcount.
linked list
Each record holds the position of the next one in its chain. Proved by checking every chain links up with no loops or strays.
chained records
No count anywhere: each record's own lengths land exactly on the next, so the walk starts from one known record and runs both ways.
archive member
A file inside the compressed archive at the end of the save, found by name in the archive's own directory.

Terms in the notes: a tid is a person's or club's id, a cid a competition's. "tid == slot index" means record k holds id k, which proves no record was skipped or invented. ff and 00 are byte values; long runs of them are padding.

Four kinds of region

Ask one question of every region: what happens to it as the career goes on? The answer tells you whether an offset or a count from another save still holds, and whether an empty-looking stretch is missing data or room not yet used.

Dead end

Ranking a gap by its printable fraction. Compressed data is 37.1% printable by construction (95 of 256 byte values), so the archive once ranked as "the most text-dense unparsed span" for a false reason. Rank by block entropy (scripts/audit/entropy_profile.py): filler ~1.4 bits/byte, records 3–6, compressed 7.9+.

The transfer band row, 143 bytes

Every transfer negotiation of the season so far, one row per bid. [u32 65,000][u32 count][2 B], then count rows of 143 bytes, row k holding k at +109. The 65,000 is a capacity; the count is exact. Read a row as a bid, never as a transfer: only the 0d row holds the agreed fee.

Quirk

The row frame starts 2 bytes after the count. Framed from the index instead (index at +8, tid at +48), each row's selling club sits at +0 of the next row, which looks like a column offset. It is a framing error: start from the header.

The sicomps archive

The archive is current state: fix_man is a two-calendar-year window and the rules are this season's. A save knows nothing of seasons before that. History comes from keeping snapshots.
